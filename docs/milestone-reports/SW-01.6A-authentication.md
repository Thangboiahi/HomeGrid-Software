# SW-01.6A — Authentication Workflows and Browser Verification

**Status:** Implementation and verification complete  
**Environment:** Node.js 24.12.0, npm 11.20.0, local Firebase Auth/Firestore emulators (`demo-homegrid`)  
**Scope:** SW-01.6A only. No deployment or production Firebase access.

## Implemented workflows

- The `/auth` page now provides responsive email/password sign-in and registration forms, inline loading and validation behavior, and generic authentication errors.
- Registration creates a Firebase Auth identity only. It does not issue a HomeGrid server session or write a profile, role, permissions, custom claims, or `userAccess` record. The page explains that access must be provisioned by a HomeGrid administrator.
- Session creation requires same-origin requests and an ID token authenticated within the existing five-minute window. Before issuing a cookie, the server validates the session, enabled Auth account, active profile, and active authoritative `userAccess` record.
- `/api/auth/session` returns a role-specific destination only after server-side session and account verification. It returns no role or permission data to the browser; the client does not determine its own destination.
- Session cookies remain HttpOnly, SameSite=Lax, five-day cookies, Secure in production. Sign-out clears the cookie and revokes refresh tokens so copied Firebase session cookies are also invalidated. Logout waits for a later one-second timestamp when necessary because Firebase revocation cutoffs have second-level precision.
- Role workspace headers and the local simulator provide a sign-out action. Authenticated users can also continue to their verified role destination or sign out from `/auth`.

## Existing security services reused

The implementation retains Firebase Client SDK email/password operations, Admin SDK session-cookie creation and verification, `requireAuthenticatedUser`, existing page guards, role permissions, Firestore `users`/`userAccess` provisioning model, and server audit writer. No RBAC rules, role grants, Firestore rules, Admin credentials, or appliance capabilities were changed. Session creation and successful session termination continue to produce audit events; audit persistence failure prevents a success response.

## Security verification

- Role values or permission claims supplied by a client are ignored. The session endpoint derives identity from the verified ID token; role access comes from the active server-side `userAccess` record.
- Missing, suspended, disabled, or otherwise inactive access cannot establish an application session. Protected API and page authorization continues to validate the revocable signed cookie and current account state.
- The session mutation endpoint rejects missing or foreign origins. Sign-out revocation and cookie clearing are exercised by the emulator test.
- Firebase Admin is imported only in server-only modules. Browser code receives no Admin credential or service-account material.
- Firestore client deny-all rules were not changed. No permission expansion or Super Admin appliance/automation capability was introduced.

## Browser verification

Using the local Next.js application and local emulators, browser interaction verified:

1. The responsive authentication page and sign-in/registration controls render.
2. Registration creates an emulator Auth identity and displays the pending-provisioning message.
3. That unprovisioned identity cannot establish a HomeGrid session.
4. After provisioning a Customer access record in the emulator only, browser sign-in redirects to `/customer`.
5. The verified active session is recognized on `/auth`; sign-out returns the page to the unauthenticated form and invalidates the session.

The browser test account and profile/access records were created only in the `demo-homegrid` emulator. The emulator process was stopped after the test; no production account was created.

## Known limitations

- Public registration is intentionally not self-service application provisioning; a trusted administrator must provision Customer or Installer access.
- Password recovery, email verification UX, and account invitation workflows were not part of this work package.
- Firebase refresh-token revocation logs out all sessions for that Auth identity, consistent with the existing revocation-verification security model.
- Emulator-backed tests emitted Firebase metadata lookup warnings in this environment. No production Firebase project or account was accessed or modified.

No deployment, role permission changes, Firestore authorization changes, appliance control, MQTT, firmware communication, or physical-device behavior was introduced. SW-01.6B has not started.
